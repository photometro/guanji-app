# 观己 App 架构搬迁方案（2026-08-09）

> 背景：产品方向升级——从单一男性自慰记录，扩张为「男性/女性/夫妻全场景 AI 赋能性健康」。
> 现状约束：app.js ~2500 行 + styles.css ~1750 行单文件；无构建工具链；本地优先架构（数据仅存本地、AI 仅聚合、无后端）。
> 目标：解决臃肿 + 组件化 + 适配远期全场景 AI 赋能性健康 + 预留其他系统改造能力（RN/多语言/云同步/鸿蒙）。
> 原则：**零用户影响**（搬移式重构不改变任何运行时行为）；**不锁框架**（React/RN 随时可上）；**数据层独立**（存储/模型/统计/AI 与 UI 解耦）。

---

## 一、目标架构形态

```
www/
├── index.html                （壳 + 导航 + 防闪烁，只引文件）
├── css/
│   ├── theme.css             （变量：深浅色板 + 液态玻璃变量 —— 必须最先加载）
│   ├── base.css              （reset + 骨架 .phone/.screen/.status）
│   ├── components.css        （通用组件：按钮/chips/卡片/seg/表单）
│   ├── tabbar.css            （tab 栏 + 滑块 + 液体变形滤镜）
│   ├── sheets.css            （记录面板/日历弹层/对话框 —— 浮层全家）
│   ├── screens.css           （首页/分析/我的/计时页）
│   ├── glass.css             （液态玻璃体系：#72-#84 全部玻璃规则 —— 横切关注点集中）
│   └── responsive.css        （媒体查询：真机/桌面矮视口/降级）
└── js/
    ├── app.js                （入口 + 导航 + 事件绑定，瘦身至 ~400 行）
    ├── storage.js            ★数据层：Preferences 读写 + 导出 + 未来 WebDAV 通道 + AES 加密
    ├── records.js            ★记录模型：CRUD + 校验 + 版本化迁移（男→多场景兼容）
    ├── stats.js              ★聚合统计：频率/时段/性别场景分桶
    ├── ai.js                 ★AI：聚合特征 → 报告 + 多人群模板注册表 + 提供商配置
    ├── ui-sheet.js / ui-calendar.js / ui-home.js / ui-analysis.js / ui-me.js
    ├── ui-timer.js           （计时流程，可从 ui-home 独立）
    └── liquid-glass.js       （液态玻璃开关 + 液体脉冲 + 主题）
```

**拆分纪律（写进规范）**：
1. **加载顺序即依赖**：CSS 变量最先、覆盖规则最后；JS 数据层 → 统计/AI → UI → 入口
2. **版本参数统一约定**：所有子文件共用 `?v=N`，bump 时整体替换（WebView 缓存管理；将来上构建工具后自动 hash）
3. **玻璃态覆盖规则全归 glass.css**（横切关注点集中一处）
4. **JS 按功能域拆**（sheet 相关全在 ui-sheet.js），不按调用方拆
5. **UI 层用纯函数组件风格**（props 传参、不直接碰 DOM API）——为 React/RN 平迁留窗口

## 二、近期（1-2 个迭代，纯重构，零用户影响）

### P1 搬移式拆分（✅ 已实施 2026-08-09）
- **JS**：函数按归属原样搬入 js/ 各文件，`<script>` 顺序加载，**全局函数/变量照旧**
- **CSS**：规则按组件原样搬入 css/ 各文件，`<link>` 顺序加载
- **组件清单（✅ 用户 2026-08-09 拍板列入）**：DESIGN-LANGUAGE → 代码组件映射（设计组件 → CSS 类 → JS 渲染 → 归属文件 → 变体/状态）——**边拆边记，顺产**；产出 `docs/component-inventory.md`，服务于复用防膨胀/多端复用/新会话上手
- 版本：子文件统一 `v=62` bump；index.html 版本 +1
- **验证**：浏览器全功能回归（console 无错 + 玻璃态 computed 全过）+ 真机 CDP（10 JS + 8 CSS 加载、两态 345/346、未来禁用、玻璃态滤镜/磨砂/深色降白全过）+ 构建安装
- **风险**：加载顺序/搬错（一次性，回归排除）；子文件缓存参数（统一 v=N 纪律）
- **踩坑记录**：①区间切在函数头（closeCalendar 491 行）→ 以函数完整闭合为边界；②顶层执行引用后加载文件函数（closeCalendar/cancelFromTimerScreen）→ 加载顺序 ui-timer → ui-sheet → ui-calendar

### P2 数据模型多场景扩展（近期内、P1 之后）
- records 增加维度：`gender`（男/女/夫妻）、`partner`（伴侣参与）、可选 `satisfaction`/`safety`/`discomfort`（温和非评判命名）
- **records.js 引入模型版本号 + 迁移函数**：老数据自动补默认维度（不丢历史）
- UI：记录面板 chips 按人群分组（男女/夫妻不同情绪诱因词）
- **TypeScript 引入时机（推荐放在 P2 开头）**：模型字段复杂化时类型收益最大；与模块化改造的构建一并引入成本最低

## 三、中期（方向落地，功能升级）

### P3 模块化改造 + TypeScript
- 转 ES Modules（或 esbuild 打包）+ 状态集中 + **引入 TypeScript**（数据模型/stats/ai 全部强类型）
- 数据层（storage/records/stats/ai）与 UI 彻底解耦，导出稳定接口

### P4 AI 多人群赋能（产品核心）
- stats：性别/场景分桶聚合（频率/时段/情绪/诱因/伴侣参与率）
- ai.js：**人群模板注册表**（男性/女性/夫妻 → 各自报告文案 + 追问引导），聚合特征 → 温和非评判报告
- 合规：免责声明 + 非医学诊断文案体系（每条模板过审）

### P5 WebDAV 备份卡
- storage.js 通道实现：CapacitorHttp（原生请求绕 CORS）+ AES 端到端加密（用户口令派生密钥）
- 设置 → 数据管理：「WebDAV 备份」卡（地址/账号/密码存本地 + 加密口令 + 立即备份/恢复/可选提醒）
- 隐私文案：数据备份到用户指定服务器，——观己不提供任何云服务

## 四、远期（战略与平台）

### F1 全场景 AI 赋能性健康完整落地
- 夫妻模式：双人记录/聚合（本地、不上云）
- 安全措施/健康节奏等温和洞察（非诊断）
- 年龄段/分级合规适配

### F2 平台扩展（触发式，不预设）
- **React Native/Expo**（触发：上架审核被 WebView 壳卡）：UI 层组件平迁（P1 的纯函数组件风格 + P4 的 TS 类型就是为此留的），数据层（storage/records/stats/ai）TS 代码可直接复用；液态玻璃 CSS 资产需换原生模糊库重做（预算外）
- **iOS**（Capacitor 兼容，需 macOS 构建）——预留
- **鸿蒙**（已搁置，但 ArkWeb 兼容 www/，预留审计即可）——预留

### F3 其他系统改造预留钩子（架构上留接口，不实现）
| 钩子 | 位置 | 未来用途 |
|---|---|---|
| storage 接口（load/save/backup/restore） | storage.js | 云同步/多设备（用户自选服务） |
| records 模型版本号 + migrate() | records.js | 任何未来字段变更安全升级 |
| AI 模板注册表 | ai.js | 新增人群/语言/风格模板即插即用 |
| 组件清单（DESIGN-LANGUAGE → 代码组件映射） | docs/ | 多端（RN/鸿蒙/网页）复用 |
| 加载顺序清单（CSS/JS 依赖文档化） | docs/ | 新人/新 AI 会话快速上手 |
| 自动化回归（Playwright 脚本固化） | debug/ | 回归面变大后的质量兜底 |
