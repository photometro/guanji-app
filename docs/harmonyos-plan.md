## 版本对标策略（2026-08-11 定）

- 鸿蒙版**从安卓 v1.0 功能基线开始重构**，**不直接对标安卓最新版（v3.10）**。
- 按版本序列逐步追赶：每个鸿蒙里程碑对标安卓一个版本区间，功能稳定后进下一个。
- 理由：快速出可用首版（约 3 周）、早期暴露 UI 重写/数据层移植的核心风险、投入分散、每版有清晰验收对照物（安卓对应版本）。
- 加密/WebDAV 等安卓 v3.7+ 功能，鸿蒙做到对应版本时再实现；加密导出包届时作为数据迁移通道自然对接。

## 调研背景（2026-08-08 ~ 08-10）

### 三条路线

| 路线 | 做法 | 成本 |
|---|---|---|
| **A. Web 套壳（推荐）** | 鸿蒙 NEXT 的 ArkWeb 直接加载现有 `www/`，Capacitor 桥换成 `javaScriptProxy`，原生能力逐个移植 | 小——复用全部前端与验证资产 |
| B. 全量 ArkTS/ArkUI 重写 | 原生重写 | 1-2 个月量级 |
| C. 鸿蒙 4.x 兼容版装 APK | 直接装现有 APK | 零成本，但 **NEXT 5.0+ 不兼容安卓 APK** |

### 路线 A 原生能力映射（核心工作）

- Capacitor 桥 → `javaScriptProxy` + `@ohos.data.preferences`
- 实况通知/魅族胶囊 → **实况窗（Live View）**（Android 16 chip 踩坑经验可迁移）
- 计时前台服务 → **长时任务 `continuousTask`** + reminderAgent
- 5 个桌面小组件 → **服务卡片**（FormExtensionAbility，2x2 需按鸿蒙规范重写 UI）
- AOD 息屏分钟 → 实况窗锁屏态
- AI 直连 DeepSeek → 同 fetch（网络权限 + https）

### 前端兼容与准备

- `www/` 为纯 HTML/CSS/JS，ArkWeb 基于 Chromium，基本原样可跑；需加 Capacitor 桥适配层（扩展 `isNativeApp` 检测，无桥降级 localStorage）
- 字体栈已预留 `HarmonyOS Sans SC`（`www/css/theme.css:42`）
- 多端复用钩子：架构文档 `docs/architecture-upgrade.md` F2 平台扩展（鸿蒙与 RN/iOS 并列，均未实施，触发式不预设）

### 工具链与环境

- **DevEco Studio**（Windows 可用）+ HarmonyOS SDK（API 12+，建议 15）+ **NEXT 真机**（实况窗/卡片/长时任务必须真机验证）+ 华为开发者账号
- 工作区已有 `harmonyos-development` skill 可辅助开发
- **第一步建议**：装 DevEco Studio + NEXT 真机，跑通「新建工程 → Web 组件加载 www/」验证兼容性
- 上架 AppGallery 对纯 WebView 套壳审核较严——个人自用可不理，上架需软著/隐私政策
