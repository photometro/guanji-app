# 观己 UI 原生化 V2 重启说明

本目录记录从 `v4.1.5` 重新开始 UI 原生化时的基线、资产取舍、失败经验和任务迁移关系。

## 唯一结论

- 代码基线：Git 提交 `c113bcf4c7729d0978ded3f37f3ab76496334af1`，`versionName 4.1.5`，`versionCode 113`。
- 原 WebView 是产品视觉、文案、交互、状态和返回关系的唯一事实来源。
- 原生化是视觉等价迁移，不是改版；#275–#281 只迁移经典/普通模式，玻璃模式不制作 Native 实现。洞悉系统改版和玻璃原生重做都必须在 UI 原生化收口后单独实施。
- 玻璃模式在 #275–#280 期间仅保留既有 WebView 作为对照/兼容路径；#281 删除全部旧 JS 核心后，玻璃模式安全回落到原生经典界面，待后置玻璃计划从 NativeRoute 直接重构，不再经过 WebView 过渡。
- App 运行时只允许一个窗口级宿主：`MainActivity`。Compose 页面、Tab、Sheet 和返回栈都属于同一个 `NativeRoot`；迁移期允许在 NativeRoot 内嵌未迁移的 WebView 内容区，但同一视觉区域不能由 WebView 和 Compose 重叠渲染。
- 旧原生化工作区只作为资产来源，不再作为继续开发的工作区。

## 不变量

1. 不删除、不重置旧工作区。
2. 不把旧 `Native*Activity` 页面实现整体复制到 V2。
3. 不在页面迁移期间改统计口径、记录语义、AI 输出策略或产品信息架构。
4. 不用 Compose 默认组件外观、默认 ripple、默认缩放或默认弹簧代替 WebView 规则。
5. 一个版本只迁移一个明确节点；未通过同状态真机对照时不得进入下一节点。
6. #275–#281 的验收只签收经典/普通模式；玻璃 Native 的材质、动效、卡片和可读性不在这些版本中实现或验收。
